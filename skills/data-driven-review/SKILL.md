# data-driven-review — 数据驱动复盘

> 纲领一句话：**每个判断都要用后台真实数据佐证「目的到底达成没」，好的延续、坏的优化、机制有问题就修正；目的只有一个——不断优化。**
> 本 skill 不抓数据（交给 `douyin-data-extract`）、不判外拓（交给 `account-strategy-gate`），只干一件事：**把「数据 → 判断 → 动作」这条复盘闭环跑标准，绝不凭印象、绝不用个案归因改口。**

## 闭环图

```
[发布前 · 盲猜预测]（预计播放/收藏 + 依据 → 写进 _predictions.md）
        │
        ▼ 发布
[T+3 对账]（预测 vs 实际，记偏差 → 校准判断依据）
        │
        ▼ ① 拉真实数据（douyin-data-extract 兜底，不靠记忆）
[播放 / 赞 / 评 / 藏 / 享 / 吸粉 / 藏播比 / 粉丝数]
        │
        ▼ ② 用数据判定「达成没」（对照四条定论，不看完播率）
[爆款三要素齐吗？收藏涨没？吸粉效率够吗？]
        │
        ▼ ③ 三动作复盘（纲领原文：延续/优化/修机制）
[好的延续成模板 · 坏的精确定位根因 · 机制 bug 改机制文件]
        │
        ▼ ④ 更新粉丝看板 + 写复盘结论
[当前粉丝 → 目标：差多少 · 月度里程碑达没到]
        │
        └──→ 依据已校准，回到下一次发布前盲猜（判断力复利）
```

## ① 拉真实数据（不靠印象）

- 固定走 `douyin-data-extract`（CDP 连本机 Chrome 9222），**禁止用记忆里的旧数字替代**。
- 每次复盘至少拿到这 7 个字段：**播放 / 点赞 / 评论 / 收藏 / 分享 / 吸粉 / 粉丝总数**；单条再补 **藏播比（藏÷播）** 和 **收藏率（藏÷赞）**。
- 缺字段就标「待补」，宁可少写结论也不编。

## ② 数据判定（定论，别再改口）

### 定论 A：收藏是播放引擎，完播率几乎无关
- 全量 109 条相关系数：收藏 **0.945**、点赞 0.943、分享 0.823、吸粉 0.867、评论 0.805、**完播率仅 0.057**。
- 爆款完播 3.24% vs 扑街 2.85%——**完播率无区分度**。
- 铁律：**盯收藏量 + 藏播比，不看完播率**。2-4% 完播是英语干货内容的正常基线，不是问题、不是瓶颈。

### 定论 B：爆款 = 反常识 × 高频动作 × 可收藏干货，三缺一即扑
- 反常识（钩子拉播放）× 大众高频动作（精准用户）× 可收藏干货（收藏燃料）。
- 动笔前先写清「反常识点 / 高频动作 / 收藏抓手」三行，**写不出不立项**。

### 定论 C：涨粉靠结果承诺，不靠播放
- 播放引擎（收藏·反常识否定）≠ 涨粉引擎（结果承诺）。
- 爆款要**双层设计**：开头反常识否定钩播放 + 结尾结果承诺钩关注。

### 定论 D：纯认知升格杀完播、不杀收藏；反常识角度定收藏下限
- **把「纯认知必扑」从铁律降级为「升格段杀留存」**：两个引擎正交，别混成一条因果。
  - 播放引擎 = 收藏量（角度对不对）↔ 留存引擎 = 完播率（升格段杀不杀）。
- **判定弃二分法，用三档**：收藏 ≥50 → 角度成立可继续做；收藏 ≥200 → 进收藏引擎；吸粉 ≥10 → 结果承诺起效。

### 定论 E：高播放规律 = 播放量级↔收藏量固定阶梯
- 结构收敛：爆款只有「反常识否定」和「结果承诺+干货」两条腿，纯观点永远不爆。
- 藏播比 ≥1.5% 是进池门槛（爆款 1.24%-3.70%，扑街 <1%）。
- 否定对象必须「公认为对、其实错、当下流行」；反「具体动作」能长出可截图干货，反「心态/情绪」必扑（2026-09-15 铁律）。

## ③ 三动作复盘（纲领核心，每次固定跑）

| 动作 | 触发条件 | 做什么 |
|:--|:--|:--|
| **好的延续** | 指标超预测线（如收藏/吸粉超预期） | 把可乘法提炼成模板，写进选题库/脚本 SOP，下一条直接复用 |
| **坏的优化** | 指标低于预测线 | 精确到根因（是钩子没反常识？是缺可收藏干货？是中段没短钩？），给一条具体改法，不许"再努力点" |
| **机制修正** | 判断/流程/选题机制本身有 bug | 改机制文件本身（选题卡选品规则、脚本审稿标准、数据口径），不靠下一次"注意点" |

**坏的优化——根因定位速查表：**
- 收藏低 → 没有「可收藏干货」，缺收藏抓手（解法：把干货做成可截图保存的清单/公式）。
- 吸粉低（粉万比 < 15）→ 缺「结果承诺」结尾钩（解法：加"多久/几步/达成什么"的确定结果句）。
- 完播崩（中段流失）→ 深度没"拆碎了喂"，连续讲道理无钩（解法：每 15 秒一个短钩/反问/停顿）。
- 不进池 → 纯认知内容，平台识别不出目标用户（解法：认知只做「场景锚定」，别脱离内容场景）。

## ③.5 盲猜预测与 T+3 对账（2026-09-20 新增 · 借鉴 cheat-on-content 机制）

**为什么加**：复盘是事后看数据，容易「我早知道」的事后诸葛。盲猜逼你在发布前把判断力押上去，对账后才能知道「判断力到底哪里准哪里偏」——这是判断力的复利，不是玄学。

**流程**：
1. **发布前（盲猜）**：发片前按定论 A–E + 同类型近 5 条数据写预测：
   - 预计播放 / 预计收藏 / 预计藏播比 / 预计吸粉
   - **必须写「依据」**（哪条定论、哪条同型作品），不许只写数字
   - 存档到 `_predictions.md`（一行一条：日期 + 作品 + 预测 + 依据）
2. **T+3 对账**：发布 3 天后拉真实数据（douyin-data-extract），先回看预测再填实际，记偏差：
   - 播放/收藏/藏播比各偏多少，判定「准 / 偏」
   - 写一句「为什么偏」——哪条依据失效
3. **校准**：连续 3 次同方向偏差（如都高估播放），主动提示升级预测依据（对照定论是否要修），不静默

**防自我欺骗（刹车）**：
- 对账顺序不能反：**先看预测，再看实际**（盲）
- 偏差记真实数字，不写「差不多」
- 预测依据要能追溯到定论/作品，不许「凭感觉」

## 铁律

1. **先拉数据再下结论**——没数据就说"待采集"，不凭印象、不用单条个案改口。
2. **判定只看定论**（收藏引擎 / 爆款三要素 / 结果承诺涨粉 / 升格杀完播不杀收藏），完播率不作为播放决策依据。
3. **三动作缺一不可**——每次都跑「延续 / 优化 / 修机制」，修机制要落到文件不落嘴。
4. **口径不混**：藏播比 = 藏÷播；收藏率 = 藏÷赞（健康值 >60%）；完播 2-4% 是基线不是问题。
5. **粉丝看板是活文件**——复盘一次更新一次，冲到目标前不看板不准收工。
6. **对照实验单变量铁律**——换锚重打 / 改版对比 / 复拍同一选题时，**一次只动一个变量**（底数=动作池、系数=钩子、抓手=收藏燃料，三者一次只改一个），否则数据回来无法归因，对照实验白做。
7. **无限游戏·不被单条数据绑架**——做号是**无限游戏**（目的=留在牌桌上继续创作），不是**有限游戏**（目的≠赢下某一条）。**纪律**：单条扑街不改定论、不代表方向错；只有触碰淘汰线（收藏<50 且吸粉<10）才换方向。数据是拿来「判断方向」的，不是拿来「喂养焦虑」的。
8. **盲猜必写、对账必跑（2026-09-20，借鉴 cheat-on-content）**——发布前不写盲猜 = 放弃判断力复利；T+3 不对账 = 这条白发。对账顺序必须「先预测后实际」，连续 3 次同向偏差必须升级依据，不许静默。
